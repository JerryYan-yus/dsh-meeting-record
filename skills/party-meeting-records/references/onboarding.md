# 首次配置与用户画像

## 首次配置

1. 用户要求“初次引导/首次配置”，或问“怎么用”且未给材料：先问工作性质，再问清单，不展开原理：

   “您主要从事哪类工作？
   1. 党建党务；2. 综合办公/文秘；3. 人事/干部；4. 财务/审计；
   5. 项目/业务；6. 宣传/群团；7. 教学/科研/医疗；8. 基层治理；9. 其他。”

   得到工作性质后，再一次性询问：
   “请提供：
   1. 单位/部门（或支部）名称；
   2. 上级单位（可选）；
   3. 补充说明（可选）；
   4. 人员名单：党建模式请按“姓名 职务 党员类别 入党时间 月党费 备注”填写，一人一行；其他模式填“姓名 职务 备注”。不确定的可留空，后续补齐；
   5. Obsidian 知识库位置（可选；不填默认 ~/Documents/机关工作知识库）。”

2. 生成前调一次 `meeting_org_info`（默认精简；需要备注/人员说明/分类汇总时才传 `verbose:true`）。
   - `configured:true`：进入正式流程。
   - `configured:false`：只发上面清单；收到后 `meeting_org_setup` 保存（必须带 `workDomain`），回：
     “已存：XX（工作性质：XX），N人；单位信息已存入知识库（<branchKnowledgePath>）。本月党费台账已按填写标准生成 X 条。请提供会议材料，或会议类型、时间、地点、主持人。记录人默认……”（党建模式记录人默认组织委员；其他模式请用户指定）。

3. 保存名单后按固定回执：

   ```text
   收到，当前支部信息：
   支部委员：张三（支部书记）、李四（组织委员）
   支部党员：王五、赵六
   补充：单位 XX；共 N 人（委员 X、党员 Y）。
   可补充：……（最多 3 条：缺关键委员、职务待确认、人数与材料不一致等）
   ```

4. 只给部分字段：保存已提供的（支部必填），缺项按清单再问一次；单位、补充说明、个人说明、知识库位置均可不填，不追问。
5. 问安装/设置：回“侧栏「会议记录」→「设置」可查看，无需安装。”不解释原理。
6. 同名成员更新职务/说明，不重复添加。
7. 未收到材料或明确会议类型前，不创建会议、不生成正文。

## 用户画像

首次使用时根据用户原话判断画像；能判断就直接 `meeting_profile_save` 保存，不追问；判断不了最多问一次：

“您的角色：支部书记 / 组织委员 / 其他支委 / 普通党员？电脑操作：不熟 / 一般 / 熟练？（记录用途：手抄 / 归档 / 上报，可不答）”

字段：`level`（novice/regular/expert）、`role`、`purpose`（handwrite/archive/report）。保存后按 `meeting_org_info` 返回的 `guidance`：

- novice：每次只给一步；用“点侧栏→填一次→复制这句话→发材料”；不解释插件/模板/专项流程；默认短长度；导出、知识库下一步再提。
- regular：简要步骤；默认中。
- expert：跳过基础，直接确认会议类型、专项流程、材料缺项；默认中/长。
- 组织委员→记录人默认本人；支部书记→主持人默认书记；手抄→短，上报→长。
- 用户明确说过写作偏好（称呼、语气、篇幅、忌讳表述）时，`meeting_profile_save(styleNotes)` 保存；生成前遵循，不保存一次性要求。
- 未判断出画像按 general；不要反复问画像。
