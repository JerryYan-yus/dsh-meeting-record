# 知识库冗余与恢复

## 自动保护

- 插件数据：每次保存 `app.json` 前保留最近 5 份备份，位于 `$DSH_HOME/meetrecord/app.json.bak-1` ～ `.bak-5`。
- 知识库快照：每次保存/删除笔记前写入 `$DSH_HOME/meetrecord/knowledge-backup.json`（最近一次全量快照）。
- 原子写入：数据文件和笔记都先写临时文件再替换，避免写一半损坏。
- 启动自检：插件启动时检查内置规范、支部信息、已保存会议记录是否缺失；缺失则调用修复。
- 面板修复：知识库页「检查修复」可手动补回规范、支部信息、会议记录、索引和快照中的材料笔记。

## 常见异常操作

| 用户操作 | 影响 | 恢复方式 |
|---|---|---|
| 删除整个 Obsidian 知识库文件夹 | 规范、支部信息、会议记录笔记全部消失；插件数据仍在 | 重启 DSH 或点“检查修复”：补回规范、支部信息、已保存会议记录、索引；材料/日常笔记从快照恢复 |
| 把知识库路径改到空文件夹 | 同上 | 重启或“检查修复” |
| 删除单篇规范/支部信息/会议记录 | 对应笔记缺失 | 启动自检或“检查修复”补回；单篇会议记录会从插件数据重建 |
| 删除索引笔记 | 索引缺失 | 下次保存/整理自动重建；也可“检查修复” |
| 删除材料/日常工作笔记 | 内容只存在笔记中 | 从 `knowledge-backup.json` 快照恢复；若快照也没有则无法恢复 |
| 重命名/移动笔记文件 | 插件按路径找不到原笔记 | “检查修复”会按类型和标题重新关联或补建；可能产生重复，恢复后人工检查 |
| 手动编辑 frontmatter/改标题 | 检索/分类可能变化 | 插件按目录分类，标题以文件内容为准；必要时重新保存 |
| 清空插件数据（app.json） | 支部、人员、会议、任务丢失；知识库文件仍在 | 把 `app.json.bak-1` 复制为 `app.json`，重启 DSH；越新的备份越接近当前 |
| 同时清空插件数据和知识库 | 插件与笔记都丢失 | 只能依赖外部备份；建议定期把 `$DSH_HOME/meetrecord/` 和 Obsidian 知识库一起备份 |
| 误点“删除数据”（15 秒确认） | 插件数据被清空 | 用 `app.json.bak-*` 恢复；知识库不受影响 |
| 删除 Word 导出文件 | 仅导出文件丢失 | 从会议记录重新导出；不会自动重建 |
| Obsidian/OneDrive 同步冲突 | 出现旧版本或重复文件 | “检查修复”补缺失；重复笔记需人工清理 |
| 磁盘满、权限错误、文件被占用 | 写入失败 | 数据文件采用临时文件+替换，通常不会写坏；处理后重试 |
| 多个 DSH/多个窗口同时操作 | 后写覆盖前写；笔记可能重复 | 当前为单用户单实例设计，避免同时编辑 |

## 恢复顺序

1. 先重启 DeepSeek Harness，触发启动自检；
2. 打开「知识库」页，点「检查修复」；
3. 若插件数据（支部/人员/会议）丢失，关闭 DSH，把 `app.json.bak-1` 复制为 `app.json`，再重启；
4. 若知识库被完全删除且快照也不存在，只能从外部备份恢复。

## 边界

- `knowledge-backup.json` 只保留最近一次快照，不是版本历史；删除后再次保存会覆盖。
- 快照保存在 `$DSH_HOME/meetrecord/`，如果该目录也被清空，则无法恢复。
- Word 导出文件不纳入快照，需要时从会议记录重新导出。
- 恢复过程不会删除现有笔记；可能产生重复，恢复后请人工核对。
